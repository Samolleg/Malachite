# Малахит: PAK и запросы к БД

Модуль и standalone не читают внешние RES/PAK: физический архив открывает хост,
модуль получает WorkspaceSnapshot и работает с MOB/скриптами. Имена `texts.res`
в навигаторе были подписями; теперь они называются связанными текстами.

Для повторных запросов добавлен weak-key индекс точных имён квестов и текстовых
ключей по неизменяемому массиву RecordDto. Скриптовые ревизии хоста могут сохранять
этот массив; изменение БД/текстов выдаёт новый. Зона квеста, регистр, неоднозначные
дубликаты и несохранённые тексты по-прежнему проверяются. SDK не меняется.

Совместный результат и подробный аудит — dbeditor `docs/testing/pak-audit215.md`
(DBPAKAUDIT215). 10000 запросов по 3787 записям: 368 → 17 мс. В реальном хосте
40 правок скрипта из 265018 символов: 602 → 341 мс суммарно, выделения памяти
UI-потока 471.5 → 195.1 МБ; пики до 124 мс остаются. Анализатор не переписан.

Malachite.PakAudit проверяет точные ссылки, зоны, регистр, дубликаты, новые тексты,
8000-строчный редактор и индекс реальных 151 MOB (7.819 с / 0.925 с с кэшем).
Пять файлов без пригодного скриптового раздела диагностированы. HostIntegration
проверяет фактический модуль с хостом 215, ввод, Undo/Redo, отзывчивость анализа,
PAK-only контекст карт и сохранение/копии на fixtures. Установленные PAK/MOB не менялись.

Исторический Malachite.Module.Verification ссылается на удалённый TextChange и
не собирается; его результат не выдаётся за успешный. Старое standalone-окно
не запускалось, проверялись поставляемый WPF-модуль и общая логика. Пакет готовится
через Build-Module.ps1, отдельно от основного комплекта; приёмка владельцем отдельно.

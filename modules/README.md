# Малахит — подключаемый модуль

Работайте со скриптами в редакторе «Код»: правка текстом, поиск/замена, автодополнение Ctrl+Пробел и подсказки при наведении. Изменения отменяются через Undo/Redo и сохраняются обычным Ctrl+S. Инструменты скрипта, шаблоны, формы редактирования и создание цепочек удалены; «+ Новый этап» вставляет только пустой Script с объявлением. Генератор по текстовому описанию также удалён; локальная модель не запускается.

В инспекторе кода используется общее объяснение команд и этапов: имена и ID из открытой MOB, единственные прямые привязки объектов из WorldScript, названия квестов и подпунктов из текущего снимка БД и связанного текста QUEST. Источник имени указан в полном объяснении. Краткая сводка показывает ожидание условий и действия по порядку; все условия и исходный код раскрываются рядом. «Ненулевое» не означает «активен», GSSetVarMax не понижает более высокое значение, KillScript оставляет уже начатые действия и прекращает дальнейшие верхнеуровневые проверки экземпляра. Это чтение исходника, а не сведения о текущей игре; просмотр не переименовывает Script и объекты и не изменяет MOB. Неоднозначные связи и неподдержанный код не угадываются.

## Работа с картами и кодом

- **Карты**: «Все карты», «Недавние», «Избранные», поиск по имени и собственной заметке. Плитки показывают дату файла и число скриптов из индекса; справа — путь, число объектов MOB, звезда и заметка. Непрочитанные данные обозначаются явно. Пометки сохраняются локально в `LocalAppData/Malachite/map-catalog.json` и не изменяют MOB или БД. Заметка сохраняется при выходе из поля, смене выбранной карты либо кнопкой «Сохранить заметку».
- **Открытые файлы** остаются во вкладках. Можно открыть другую карту с несохранённым текстом; при возвращении сохраняются выделение, прокрутка и выбранный режим. Ctrl+Tab / Ctrl+Shift+Tab переключают вкладки, Ctrl+W или × закрывают выбранную с проверкой несохранённых изменений. Поддерживаются до 64 вкладок. Восстановление сеанса включает все открытые файлы; новая сессия хоста не получает разрешение перезаписать исходник только из recovery.
- **Код** постоянно в центре. Инспектор справа следует за курсором: команда, «Когда / Тогда» текущего блока, название, полный ключ, описание и подпункты квеста из texts.res. Связи MAL09 и переходы к строкам сохранены в раскрываемом обзоре квеста. Неизвестные связи не угадываются.
- **Сохранить изменения / Ctrl+S** сохраняет открытые исходные документы через хост. Undo/Redo остаются общей историей редактора; если операция изменила другую вкладку, она открывается. «Копии» сохраняют отдельный файл. Переход из индекса в изменённую вкладку останавливается, чтобы устаревшая позиция не указала на другой код.
- **Проверки** сворачиваются отдельной кнопкой; F5 выполняет статическую проверку. Навигатор, код и Инспектор постоянно видны, разделители меняют ширину колонок. Игровую проверку выполняет владелец.

Вкладки с общей историей доступны в основном Редакторе БД, предоставляющем `documents.session.v1` и `transactions.v1`. В минимальном хосте без этих служб сохраняется прежняя работа с одним документом.

Модуль предназначен для SDK ModuleContracts V1 draft r5 и совместимого хоста Редактора БД. Это отдельная библиотека, а не самостоятельный EXE. Хост предоставляет contracts DLL; не копируйте их дубликаты в каталог модуля. Модуль не ссылается на App/Core редактора.

Обычное независимое обновление из корня workspace (Редактор БД должен быть закрыт):

```powershell
./EvilIslands.QuestStudio/Update-Module.ps1
```

Команда берёт SDK из постоянной установки `EvilIslands.DatabaseEditor/handoff/current`, собирает только Малахит во временную папку и передаёт пакет штатному `EvilIslands.DatabaseEditor/tools/Update-Malachite.ps1 -PackagePath`. Проверки совместимости, закрытого редактора и обновление host-manifest выполняет хост. App/Core редактора не пересобираются. Датированные комплекты не создаются. Для сборки без обновления используйте `-BuildOnly`; путь временного пакета выводится в конце и сохраняется для диагностики. После успешного обновления откройте редактор из той же папки `current`.

Сборка отдельного пакета с явно выбранным SDK (для разработки контракта):

```powershell
./EvilIslands.QuestStudio/Build-Module.ps1 -ModuleSdkDir '<готовый SDK>' -PackageDirectory '<новый каталог пакета>'
```

Результат: Malachite.Core.dll (чтение MOB, анализ, справочники), Malachite.UI.Wpf.dll (UserControl), Malachite.Module.dll (подключение к хосту). Core компилирует общие источники standalone-версии, дубликата парсера нет. Старый самостоятельный редактор остаётся доступен для регресса; его Window не используется при встраивании.

Размещение в постоянном хосте: `Modules/malachite/current`. Обновлением управляет штатный скрипт хоста; вручную второй пакет в Modules не добавляйте — загрузчик отвергает одинаковые moduleId. Hot reload не поддерживается. `Build-Module.ps1` только собирает пакет; `Update-Module.ps1` также вызывает установку в current. Игра этими командами не изменяется. Изменения SDK и новые возможности хоста согласуются с задачей «Редактор БД»; совместимые обновления Малахита выполняются независимо.

Постоянный каталог не задаёт версию модуля. Значение `0.4.0`, сохранённое в старых метаданных и сборках, не является актуальной пользовательской ревизией. Отдельный номер сборки ещё не реализован; точную идентичность пакета определяет его manifest. Датированные отчёты с прежним путём не переписываются.

Модуль использует документы и общий журнал хоста: ввод публикуется сразу, Ctrl+Z/Y вызывают общую историю. «Сохранить изменения» и Ctrl+S вызывают общее сохранение редактора БД: открытый MOB записывается обратно в исходный MOB, открытый текст или проект — в свой исходный файл. Хост проверяет внешние изменения и делает резервную копию. Для нового документа хост предложит выбрать файл. Если сохранение отменено или не удалось, изменения остаются несохранёнными.

Меню «Копии» создаёт отдельный MOB/текст или рабочий проект .malachite. Проект открывается в Малахите; игра его не читает. Создание копии не сохраняет исходный документ и не снимает отметку о несохранённых изменениях. Recovery v2 сохраняет последний символ и неприменённую карточку, включая включение else; v1 читается с известным ограничением старого формата, в котором checkbox не сохранялся.

При открытии БД хост с возможностью `workspace.maps-cache.v1` автоматически ищет `<папка БД>/Maps`, затем `<родитель папки БД>/Maps` (например, `res/database.res` и соседняя `Maps`). Обрабатываются MOB непосредственно в найденной папке. Кэш индекса хранится хостом в профиле пользователя отдельно для каждого полного пути БД. При повторном открытии файлы читаются для проверки SHA-256; неизменённые сценарии повторно не разбираются. Изменённые/новые карты и обновление парсера обновляют индекс; удалённые карты исключаются. Названия, тексты и эффекты брифингов берутся из текущего снимка БД, не из кэша. Повреждённый кэш перестраивается. «Папка MOB…» позволяет вручную выбрать другую папку на текущий сеанс. В старом хосте сохраняется ручная индексация. Индекс не заменяет сохранение правок MOB.

`DocumentCodec`: owner `malachite`, format `malachite-script`, version 2; artifact kinds `malachite-project`, `mob`, `script-text`. Неизвестная версия recovery не заменяет текущий документ. Исходный контейнер MOB включён в состояние для восстановления. При конфликте общий документ не перезаписывается, локальный ввод остаётся в recovery.

Регистрация документа явно передаёт SaveArtifactKind: исходный .mob → mob, .txt/.scr → script-text, .malachite и новый документ → malachite-project. Наличие MOB внутри проекта не меняет формат. В recovery сохраняется этот выбор; при восстановлении без прежнего host document создаётся новая регистрация без выдуманного разрешения на запись исходника. Старый recovery без поля формата безопасно восстанавливается как проект. Хост сохраняет SourceToken и SaveArtifactKind отдельно от Undo.

Раздел «Связанные данные БД» читает актуальные снимки квестов/брифингов и текстов, включая несохранённые правки; двойной щелчок ведёт к записи. Изменения БД здесь пока не редактируются отдельными полями. Полная автоматическая реконструкция цепочки MOB→QDB→диалог, игровые вычисляемые связи и компиляция движком не заявляются.

Рабочее пространство MAL15: навигатор слева, код в центре, Инспектор справа. Старый Обозреватель, вкладки «Функции»/«GS», панель «Данные БД» и отдельный экран «Квесты карты» удалены.

Индекс папки использует optional `IModuleFileBrowser`/`files.browse-folder.v1`; хост выбирает папку и читает только разрешённые пути. При отсутствии возможности кнопка недоступна с объяснением. Прямых файловых диалогов/записи в модульном UI нет; чтение MOB по ссылкам тоже проходит через хост.

Контракт ещё draft: общий SaveAll/recovery и повторное открытие сеанса проверяются совместно с владельцем хоста. Автоматические проверки модуля не заменяют ручную проверку окна Редактора БД и игровых сценариев. Собственный UI не изменяет глобальные ресурсы WPF и не создаёт Application/Window.

Связи с БД: наведите на имя QuestComplete или его строковый ключ квеста — подсказка показывает запись quests.quests, связанные тексты и кнопку перехода в БД. Точное совпадение строкового литерала с ResourceKey также показывает найденные связанные тексты, но не объявляется доказательством семантики вызывающей функции. Переход к записи доступен из подсказки или по Ctrl+Enter; при неоднозначной ссылке показывается пояснение. Тексты включают несохранённые изменения и обновляются по событию хоста. Не найденный ключ относится только к текущему снимку; вычисляемые ключи, escape-последовательности и неоднозначности не угадываются. ID MOB, GS-переменные, спецификации предметов и QStart пока не связываются с БД автоматически. Проверка существования показывается в контекстной справке, не добавляет ложных ошибок компиляции. Автодополнение и создание записей не входят в этот первый этап.


GS-квесты: GSGetVar / GSSetVar / GSSetVarMax / GSDelVar с буквальным ключом q.зона.квест[.подпункт] связаны с quests.quests и секцией #subobj в текущем тексте QUEST. Показаны имя задания, название/описание точного подпункта и смысл 0/1/2/3 (неизвестен, доступен, выполнен, провален). Max описывается как максимум, не как безусловная активация; GS-запись не приравнивается к QuestComplete/награде. Текущее игровое значение неизвестно, показ подпункта зависит от родительского квеста. Отсутствующие/повторные маркеры явно отмечены. Подсказка, Ctrl+Enter и панель ведут к родительской записи квеста; отдельного адреса подпункта в SDK нет. Неизвестное SSetVarMax без G не подменяется известной командой. Объяснения состояний основаны на обработчиках журнала и актуальных текстах; живой игровой прогон не выполнялся.

Редактор кода: подсветка обновляется сразу при вводе (ключевые слова — малахитовые, вызовы — голубые, строки — золотистые, числа — сиреневые, комментарии — приглушённые). Поддержаны // и /* */; скобки в строках и комментариях не участвуют в поиске пары. Возле курсора выделяются обе парные круглые скобки. Ctrl+Пробел открывает команды, объявления скриптов и ключевые слова; список также появляется после двух букв имени. Стрелки выбирают вариант, Enter/Tab вставляют, Esc закрывает. Вставка заменяет имя целиком, сохраняет существующие аргументы и добавляет () только когда их ещё нет. Общие Undo/Redo хоста сохраняются. В строках/комментариях список не предлагается. Под кодом отображаются сигнатура и русский смысл текущего аргумента, включая незакрытые вложенные вызовы. Это помощь для основного исходного кода, не автоматическая генерация значений аргументов и не компилятор игры.

Навигатор «Квесты» выбран по умолчанию: задания текущей карты по правилу MAL10. Раскрытие показывает выдачу, именованные подпункты, завершение/провал и проверки; каждая запись содержит состояние, Script и строку. Порядок групп не утверждает единственную сюжетную цепочку. Выбор записи переводит курсор в код. Обзор квеста раскрывается в Инспекторе. Квесты с проверками состояния, без подтверждённой выдачи, продвижения или завершения в скриптах этой карты, вынесены вниз в свёрнутую строку «Только проверяются здесь · N». Обзор строится для выбранного задания по всем проиндексированным картам; группы и отдельные записи раскрываются по запросу. Разбор открытых карт, межкартовый индекс, связи и объяснения готовятся в фоне с надписью «Индексируется…»; результат прежнего выбора не заменяет новый обзор. Разбор и объяснения переиспользуются на карту до изменения текста, MOB или снимка БД. Название и подпункты берутся из текущего снимка БД / текста QUEST. Группы «Где состояние меняется», «Кто его проверяет», «Какие задания зависят от него» показывают карту, Script, строку и общий с Инспектором ScenarioExplanation: имена объектов, условия, смысл значений квеста и соседние действия. Брифинги добавляют выдачу/завершение из полей QDB 6/7, ссылки показывают использования состояния разговора без обещания его прохождения. Щелчок ведёт в «Код» на строку либо к записи БД. Дочерние Script и соседние задания раскрываются по запросу; прямой вызов не означает ожидания его завершения.

Связи по общим GS-ключам, включая произвольные имена вне q.зона.квест, обозначены «возможная зависимость». Известные совместимые запись и проверка показаны с причиной; это не порядок прохождения. Для общего ключа из Инспектора доступен такой же обзор его использований. Состояния 0/1/2/3 относятся только к квестам, произвольным ключам смысл не назначается. На GS-строке или QuestComplete в Инспекторе — «На других картах: пишут N · проверяют M», раскрываемые переходы и «Весь квест». Количества относятся к обращениям в исходниках по ключу / заданию, не к событиям игры; контексты игроков указаны у каждого обращения. Эффекты брифингов БД показаны отдельно в обзоре.

«Просмотренные карты и пробелы источников» перечисляет пути, версии источников и ошибки разбора/индекса; вычисляемые ключи отмечены как неизвестные. Все открытые вкладки заменяют диск текущим текстом, включая несохранённый локальный ввод; неприменённые поля конструктора не считаются кодом. Ссылки проверяют версию текста или MOB перед переходом. Индекс диска обновляется при сканировании папки, на движение курсора не перестраивается; разбор открытых текстов и объяснения кешируются до изменения источника / снимка БД. Удалённые или новые файлы обнаруживаются при следующем сканировании. Старый восстановленный индекс без текста явно требует обновления. Неизвестные внешние события, ненайденный источник запуска, отсутствующие карты/БД и состояние сохранённой игры остаются пробелами. Обзор только читает исходники и не меняет MOB.

## Старое пользовательское состояние

Открытые документы, вкладки, курсор и прокрутка восстанавливаются. Неизвестный или удалённый режим открывается как «Код». Неприменённый черновик карточки из старого recovery сохраняется: перед продолжением можно перенести его в код, явно отбросить или отменить действие. До решения код защищён от редактирования. Новые карточки не создаются.

Пользовательская библиотека %LOCALAPPDATA%/Malachite/script-templates.json больше не читается и не записывается. Сам файл не удаляется. Черновики конструктора были только в памяти сеанса; окно инструментов и шаблонов не сериализовалось.

Подсказки объектов исходной MOB, история переходов Alt+Left/Right и переход к объявлению F12 сохранены отдельно от удалённого окна. Инспектор только объясняет исходник, включая «Когда / Тогда»; добавление действий, шаблонов, правка условий/ветки и добавление вызова через карточку удалены.

## Навигатор MAL15

«Скрипты» показывает все Script и WorldScript: группы WorldScript / Квестовые / Объекты и NPC / Прочие и фильтр группы. Автоназвание берётся из первого блока «Когда / Тогда»: первая проверка → изменение подтверждённого квеста, затем подпункта, затем первое действие. Техническое имя и строка всегда рядом; подсказка содержит полное превью и число условий/действий. Неточные технические описания помечены «контекст в коде», исходные имена не меняются.

Поиск вверху обоих видов учитывает название и связанные тексты квеста, имя Script, код и объяснения с именами объектов/NPC. Результаты — места в коде (по строкам); счётчик относится к местам, а не числу Script. Фильтр группы применяется в виде «Скрипты». Подготовка данных идёт в фоне; при изменении текста устаревший переход блокируется до обновления. Раскрытые группы образуют один плоский виртуализированный список с Pixel/Recycling, без вложенных списков и изменений толщины рамки при наведении.

«+ Новый этап» создаёт уникальное имя NewStageN и DeclareScript, вставляет пустой Script после текущего блока (между блоками — перед следующим), сохраняя переводы строк. Курсор ставится внутрь if. Условия, действия и запуск заполняются кодом; квестовые значения, награды и вызовы автоматически не добавляются. В исходном языке MOB тела заключены в круглые скобки. Незавершённый каркас требует заполнения перед использованием в игре.

## Компиляция текущего текста (F5)

F5 / «Проверить» передаёт текущий несохранённый текст в поставляемый
`tools/ScriptCheck/ScriptCheck.exe --stdin`. Кодировка Windows-1251 строгая:
непредставимые символы дают явную ошибку без замены. Компиляция асинхронная,
ограничена 30 секундами; новый F5, правка текста, смена карты и закрытие модуля
отменяют предыдущую проверку. Устаревший результат не показывается.

Сверху панели «Проверки» показаны компилятор EIRebuild с коммитом и результат.
Нажатие на ошибку переводит к строке и выделяет её. Статические проверки
Малахита остаются ниже, независимо от результата компилятора. Недоступность,
сбой или некорректный ответ утилиты являются ошибкой, а не успешной проверкой.
Каждый MOB компилируется самостоятельно: вторичный AddMob не наследует
глобальные переменные и группы родителя и может сообщать о неизвестных именах.
Проверка не исполняет сценарий и не подтверждает игровые ссылки и поведение.

Утилита x86 поставляется со статическими CRT/MFC, дополнительные VC++/MFC DLL
не требуются. `manifest.json` содержит полный коммит EIRebuild и SHA-256 EXE.
Build-Module принимает `-ScriptCheckRoot` (по умолчанию рабочее дерево MAL18),
проверяет чистое закоммиченное состояние и соответствие записи коммита сборки.
Сначала собрать ScriptCheck из этого состояния, затем обычный Update-Module.
App/Core хоста и SDK при этом не пересобираются.
